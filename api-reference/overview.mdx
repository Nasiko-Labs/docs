Nasiko exposes a single HTTP API from the control plane — the same API that the CLI, the web UI, and the platform admin tools use under the hood. Everything from deploying an agent to querying a trace is available as a REST or JSON-RPC call.

<Note>
  The full interactive endpoint reference is coming soon. In the meantime, the rest of these docs document each area of the API (agents, orchestration, observability, secrets, MCP, and access control) in context, with example requests.
</Note>

## Authentication

Most `/api/*` routes expect a bearer token from a normal login session. A few surfaces use other credential types suited to their caller:

- The agent-facing MCP gateway (`/api/mcp`) is authenticated with a scoped delegation token, not a session token.
- The embedded image registry (`/v2/*`) accepts registry-style Basic or Bearer credentials so that standard container tooling can push and pull images.

See [access control](/onboarding/acl/overview) for how permissions are evaluated once a request is authenticated.
