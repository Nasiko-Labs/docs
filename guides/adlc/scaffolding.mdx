---
title: "Scaffolding a new agent"
description: "Generate a new agent project from a template, then generate or refresh its AgentCard.json."
---

Every agent project on Nasiko is built around the same two files: an `AgentCard.json` — the single
source of truth for the agent's identity — and a `Dockerfile`. `nasiko new` scaffolds both from a
template so you're never starting from a blank directory.

## Project structure

```
my-agent/
  AgentCard.json          # you manage this (or `nasiko card` generates it)
  Dockerfile              # you manage this (or `nasiko new` scaffolds it)
  src/                    # your agent source code
  .nasiko/agent.json      # auto-created by `nasiko deploy` — do not edit, add to .gitignore
```

`AgentCard.json` carries:

- **name** — the agent's unique identifier on a cluster
- **version** — the image tag used for deploys, e.g. `0.1.0`
- **description** and **skills** — what the agent does and exposes, as described in
  [A2A agents and frameworks](/guides/a2a-agents-and-frameworks)
- **capabilities** — streaming, push notifications, and other feature flags
- **url** and **protocolVersion** — the agent's endpoint and A2A version

`.nasiko/agent.json` is written the first time you `nasiko deploy` — it links your local directory
to a specific agent ID on the cluster, so later deploys update that same agent instead of creating a
new one.

## Scaffold a project

```sh
nasiko new                      # interactive — pick a template
nasiko new openai my-agent      # from a named template directly
nasiko new claude-sdk my-agent  # another named template
```

Run without arguments, `nasiko new` walks you through choosing a template interactively, pulling
options from the artifact registry your CLI is connected to (Nasiko's public registry is connected
by default — see [the artifact registry](/guides/artifact-registry)). Given a template name
directly, it scaffolds from that template without prompting.

<Tabs>
  <Tab title="Python">
    Templates cover several agent frameworks, including OpenAI's Agents SDK, Anthropic's SDK,
    CrewAI, LangChain/LangGraph, and Google's Agent Development Kit — pick the one closest to what
    you already use.
  </Tab>
  <Tab title="Rust">
    Templates build directly against an A2A server implementation — a thin `main.rs` plus a

  </Tab>
  <Tab title="Go">
    Templates build directly against an A2A server implementation, following the same shape as the
    Rust templates.
  </Tab>
</Tabs>

Whichever template you pick, scaffolding produces a project directory with an `AgentCard.json`, a
`Dockerfile`, and starter source code that already implements the A2A contract — you fill in the
skill logic.

## Generate or update the agent card

```sh
nasiko card "A code review agent that finds bugs in PRs"
nasiko card                     # omit the description to auto-detect from source
nasiko card --dir ./my-agent    # target a specific directory
```

When your CLI is connected to a cluster, `nasiko card` uses an LLM to read your source code and
description and produce an `AgentCard.json` — skills, capabilities, and all. Disconnected, it falls
back to interactive prompts so you can still hand-author the card.

Re-run `nasiko card` whenever you add or change a skill; the card is what the platform reads at
deploy time to populate the agent registry; the platform doesn't watch your source for changes.

## Validate before you build

```sh
nasiko validate
```

Checks that `AgentCard.json` and `Dockerfile` both exist and are well-formed before you sink time
into a build that will fail for a structural reason. Run it right after scaffolding, and again
before your first deploy.
